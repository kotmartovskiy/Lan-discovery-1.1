# Полезные команды

## SSH и доступ

```bash
ssh root@192.168.3.234          # основной LAN-адрес (пароль: 1234)
ssh root@192.168.3.235          # WiFi AP — работает, когда LAN-кабель не подключён
```

Если `192.168.3.234` не отвечает: проверьте физический линк (`ip -br addr show end0` — должен быть `UP` без `NO-CARRIER`) и DHCP-lease. Панель при этом продолжает работать по `.235`.

## Сервис

```bash
systemctl status lan-discovery --no-pager
systemctl restart lan-discovery
journalctl -u lan-discovery -f                 # живой лог
journalctl -u lan-discovery -n 200 --no-pager  # последние 200 строк
```

> ⚠️ Не перезапускайте сервис во время клонирования SD (см. [SD-клонирование](https://github.com/kotmartovskiy/Lan-discovery-ARM/wiki/SD-клонирование)).

## Редактирование кода на сервере (регламент)

```bash
# 1. бэкап — обязательно
cp /opt/lan-discovery/app.py /opt/lan-discovery/app.py.backup-$(date +%Y%m%d-%H%M%S)

# 2. синтакс-проверка
python3 -c "import py_compile; py_compile.compile('/opt/lan-discovery/app.py', doraise=True)"

# 3. рестарт
systemctl restart lan-discovery
```

Из Windows удобно `deploy.py` (бэкап → SFTP → проверка → рестарт) или `remote_edit.py`.

## Диски и хранилище

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,FSTYPE
df -h
du -sh /srv/media/* 2>/dev/null
findmnt /srv                                  # HDD смонтирован?
```

HDD `/dev/sda1` (метка `data`) монтируется на `/srv` из `fstab` c опцией `nofail`:
загрузка **не ждёт** его — `srv.mount` встаёт после `local-fs.target`.

### Зависимость сервисов от HDD

Из-за `nofail` сервисы, которым нужны данные с диска, стартовали раньше монтирования
и видели пустую папку. Поэтому добавлены systemd drop-in'ы:

```ini
# /etc/systemd/system/transmission-daemon.service.d/hdd.conf
[Unit]
RequiresMountsFor=/srv/downloads

# /etc/systemd/system/minidlna.service.d/hdd.conf
[Unit]
RequiresMountsFor=/srv/media /srv/downloads

# /etc/systemd/system/lan-discovery.service.d/hdd.conf  (только порядок,
# без Requires — панель должна подниматься даже без HDD для диагностики)
[Unit]
After=srv.mount
```

После правки: `systemctl daemon-reload && systemctl restart transmission-daemon minidlna`.
Бэкапы юнитов — `/root/systemd-backup-<дата>/`.

### Доступ к файлам по сети

| Протокол | Адрес | Данные |
|---|---|---|
| Samba | `\\192.168.3.235\downloads`, `\media`, `\share` | логин `kot`, пароль свой (в репозиторий не заносится) |
| DLNA | `http://192.168.3.235:8200` («Orange Pi DLNA») | индексирует `/srv/media` и `/srv/downloads` |
| Transmission Web | `http://<ip>:9091/transmission/web/` | скачанное — `/srv/downloads` |

`192.168.3.234` отдаётся только при подключённом LAN-кабеле; без него
используйте `.235` (WiFi AP) — в том числе в адресах шар и DLNA.

Проверка Samba с Windows:

```powershell
net use \\192.168.3.235\downloads /user:kot <пароль>
dir \\192.168.3.235\downloads
```

Смена пароля Samba: `smbpasswd kot` (учётка отличается от системной).

## База данных

```bash
sqlite3 /opt/lan-discovery/devices.db ".tables"
sqlite3 /opt/lan-discovery/devices.db "select count(*) from devices"
sqlite3 /opt/lan-discovery/devices.db "select max(timestamp) from weather_observations"
```

Бэкапы БД кладёт `backup-db.timer` каждый час (скрипт `/usr/local/sbin/backup-db.sh`).

## Сеть

```bash
ip -br addr
ping -c 3 192.168.3.1

```

Полезные порты: `8080` — панель, `9091` — Transmission Web, `9090` — Netdata (если установлен), `5000` — `weather-monitor`.

## Типовые неполадки

| Симптом | Что проверить |
|---|---|
| Пустая страница / `ERR_EMPTY_RESPONSE` на IP | Сервис жив? `systemctl status lan-discovery`; в адресной строке правильный IP (`.234` vs `.235`)? |
| Жёстко зашитый IP в iframe (раньше `/torrent`) | Ссылки внутри панели должны использовать `window.location.hostname`, а не конкретный IP |
| Бейдж IPTV «ОШИБКА» | `journalctl -u update-iptv.service -n 60` — обычно ночной запуск не смог достучаться до источника |
| Не меняется шаблон | В проде `TEMPLATES_AUTO_RELOAD` выключен → нужен `systemctl restart lan-discovery` |
| `sd_present: false` при вставленной карте | `lsblk`, физическая посадка карты, `/api/sd-info` |
| Панель отдаёт `NaN` в статусе SD | Исправлено: `/api/sd-info` возвращает явные `null` |
| Transmission: «No data found! Ensure your drives are connected» | HDD смонтировался после старта daemon (fstab `nofail`) → drop-in `RequiresMountsFor=/srv/downloads`, затем `systemctl restart transmission-daemon`; данные на месте — проверить `ls /srv/downloads` |
| По сети не видно медиафайлы (DLNA пусто) | Индекс minidlna строился до монтирования `/srv` → drop-in + `systemctl restart minidlna`; проверка: `sqlite3 /var/cache/minidlna/files.db "select count(*) from details where path like '%.mkv'"` |
| Windows: ошибка 86 «Сетевой пароль указан неверно» | Шары требуют пользователя `kot` (не гостя) — `net use ... /user:kot <пароль>`; сброс: `smbpasswd kot` |
| Windows: ошибка 53 / путь не найден по `.234` | LAN-кабель отключён → используйте `192.168.3.235` |
