# Клонирование eMMC → SD-карта

Функция делает полную побайтовую копию внутренней eMMC одноплатника (X96 Max, `/dev/mmcblk2`) на SD-карту — чтобы перенести систему на другую плату или получить резервный носитель. Ранее использовалась на Orange Pi.

## Диски в системе

| Устройство | Назначение | Размер |
|---|---|---|
| `/dev/mmcblk2` | **eMMC** (источник, текущая система) | ~14.6 ГБ |
| `/dev/mmcblk0` | **SD-карта** (приёмник) | ~29.1 ГБ |
| `/dev/sda` | HDD (данные) | ~232.9 ГБ |

## API

| Роут | Что делает |
|---|---|
| `POST /api/clone/start` | Запускает клонирование (только `admin`) |
| `GET /api/clone/status` | Прогресс: `running`, `ok`, `error`, `percent`, `text` |
| `GET /api/sd-info` | Наличие/размер/модель SD, точка монтирования, `used`/`total`; при отсутствии — `found: false` и `null`-поля (не `NaN`) |
| `GET /api/status` | Возвращает `sd_present`, `sd_size`, `sd_writing` для нижней панели |

## Как это работает

```
POST /api/clone/start
  ├─ если уже идёт копирование → {"ok": true, "running": true}
  ├─ rate-limit: не чаще 1 раза в час (429 "too fast, wait 1 hour")
  ├─ проверка наличия /dev/mmcblk0
  └─ фоновый поток:
       sync
       dd if=/dev/mmcblk2 of=/dev/mmcblk0 bs=4M status=progress
       ├─ поток-_наблюдатель парсит stderr и обновляет percent/text
       ├─ exit code 0 → sync → {"ok": true, percent: 100}
       └─ иначе → сохраняется stderr[:200] как error
```

- Прогресс живёт в состоянии копии (state-файл), поэтому после **рестарта сервиса** страница восстанавливает его через `initCloneStatus()` — а сам `dd` при рестарте, к сожалению, убивается.
- Защита от «зависшего» состояния: если запись помечена `running`, но процесс `dd` уже не жив (`_clone_dd_alive`), состояние сбрасывается.

## Отображение в интерфейсе

Нижняя панель (`templates/base.html`, поллинг `/api/status` каждые ~3 с):

- `sd_present` + не смонтирована → **«29.1 ГБ (не смонтирована)»**;
- `sd_writing` → **«29.1 ГБ (идёт запись)»**;
- карта не вставлена → «извлечена».

Прогресс-бар копирования показывает `percent`/`text` из `/api/clone/status`, опрос идёт до завершения.

## Правила безопасности

> ⚠️ **Нельзя перезапускать `lan-discovery` во время `dd`** — процесс будет прерван, карта останется с неполной копией.

> ⚠️ Убедитесь, что SD-карта действительно лишняя: запись **уничтожает** всё её содержимое безвозвратно.

> ⚠️ **Guard:** если система сейчас загружена с SD-карты, клонирование запрещается —
> API вернёт `409` с причиной, кнопка в интерфейсе отключена (иначе `dd` перезаписал бы
> загрузочный носитель). Аналогично: **бэкап eMMC не выполняется** при загрузке с SD
> или без подключённого HDD — статус и причина видны на вкладке «Система»
> и в `/api/backup-status`.

Рекомендуемый порядок:

1. Вставить SD-карту, дождаться появления в нижней панели.
2. `GET /api/sd-info` → `found: true`, размер совпадает с ожидаемым.
3. Запустить клонирование из веб-интерфейса (раздел «Система» → SD).
4. Не трогать сервис до `percent: 100` / «Готово!».
5. Проверить: `lsblk -f`, размер файлов на карте.

## Ручная диагностика

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,FSTYPE
cat /sys/block/mmcblk0/size          # секторы SD
systemctl status lan-discovery --no-pager
journalctl -u lan-discovery -n 100 --no-pager | grep -i -E "clone|dd|sd"
```
