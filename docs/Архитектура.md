# Архитектура

## Общая схема

```
Браузер ── HTTP :8080 ──> Flask (app.py)
                             │
        ┌────────────────────┼──────────────────────┐
        │                    │                      │
   modules/*            Jinja2 templates        фоновые потоки
   (роуты/логика)       (base.html + ...)       и schedule-задачи
        │                    │                      │
   core/*                                            │
   hardware/discovery/events/module_loader           │
        │                                            │
        └─────────────── SQLite devices.db ──────────┘
                        JSON в /etc/lan-discovery/
```

## Точка входа — `app.py`

`app.py` — «сборщик»:

1. Инициализация: `Flask`, `CSRFProtect`, `SECRET_KEY` из `/etc/lan-discovery/secret.key`, логирование, соединение с `devices.db`.
2. Порядковая регистрация модулей (каждый экспортирует `register_routes(app)`):
   ```python
   from modules.auth import register_routes as register_auth_routes
   from modules.module_manager import register_routes as register_module_manager_routes
   from modules.devices_routes import register_routes as register_devices_routes, start_scan_thread
   from modules.weather_routes import register_routes as register_weather_routes
   from modules.system_routes import register_routes as register_system_routes, service_state
   from modules.network_routes import register_routes as register_network_routes
   from modules.media_routes import register_routes as register_media_routes
   from modules.monitoring_routes import register_routes as register_monitoring_routes
   from modules.inventory_routes import register_routes as register_inventory_routes
   from modules.core_routes import register_routes as register_core_routes
   ```
   В `app.py` не остаётся роутов — только инфраструктура (Flask/CSRF, контекст
   `blocks_for`, шаблоны через `ChoiceLoader`), фон (`schedule`: курсы — 6 ч,
   переработка — 24 ч, сканер сети, `retention_loop` событий) и `main`.
3. Миграции/схема — `modules/devices_routes.py`: карта `MIGRATIONS`
   ((1, v1), (2, v2)) применяется последовательно по `PRAGMA
   user_version`, плюс `_ensure_extra_tables` поднимает 8 серверных
   таблиц на старых БД — см. «Данные».
4. Манифесты модулей (`modules/<id>/module.json`) читает `core/module_loader.py`:
   навигация вкладок, плитки `/apps`, справка `/help`, слоты блоков (`blocks_for`);
   каталог из GitHub — `core/module_catalog.py`.
5. `Flask-SocketIO` — события реального времени (живой прогресс долгих операций).

Общие помощники: `_cmd()` (запуск команд с таймаутом), `_cfg()` (чтение конфига), `page_data` (данные для шаблонов), `service_state()` (обёртка над systemd).

## Ядро — `core/`

| Модуль | Ответственность |
|---|---|
| `core/hardware.py` | `detect_platform()` (OP/X96/generic), температура CPU, info по дискам — без жёстких `thermal_zone0`/`mmcblk2` |
| `core/discovery.py` | сканер LAN: scanner → normalizer → reconcile (MAC/IP-диффы, события) |
| `core/events.py` | журнал событий v2: `emit(severity/source/metadata)`, `cleanup_old_events`, `retention_loop` (events.retention_days, default 180, 0 = выкл) |
| `core/module_loader.py` | манифесты `module.json`, навигация, справка, слоты блоков |
| `core/module_catalog.py` | каталог модулей: index.json + установка/обновление из GitHub |

## Шаблоны

- `base.html` — каркас: шапка с часами, меню, **нижняя панель статуса** (CPU/RAM/сеть/SD/копирование), опрос `/api/status` каждые ~3 сек; csrf-meta + fetch-обёртка (автоподстановка `X-CSRFToken`).
- `base_app.html` — упрощённый каркас для внутренних приложений (тоже с csrf-meta).
- `templates/apps/*.html` — содержимое вкладок на странице `/apps` (подгружается через `<iframe src="/apps/nettools">` и т.п.).
- `modules/<id>/block.html` — partial'ы блоков (`type: block`); ищутся через `ChoiceLoader`
  (`templates/` → `modules/`), подключаются циклом `blocks_for("<slot>")`.
- `modules/<id>/help.md` — справка модуля, рендерится в конце `/help` (манифест `help: true`).
- `games/*.html` — статические игры, отдаются роутом `/games/<path:filename>`.

Важно: `TEMPLATES_AUTO_RELOAD` выключен (debug=False) → **после правки шаблона нужен рестарт сервиса**.

## Данные

SQLite `devices.db`, схема поднимается картой `MIGRATIONS` по
`PRAGMA user_version` (сейчас **2**). Фактический состав (14 таблиц):

| Группа | Таблицы |
|---|---|
| Устройства | `devices`, `device_inventory` |
| События | `events` (retention: `events.retention_days`, default 180 дней) |
| Погода | `weather_observations`, `weather_hourly`, `weather_daily`, `weather_forecast`, `weather_forecast_history`, `weather_alerts`, `mchs_alerts` |
| Финансы | `currency_rates`, `currency_history`, `recycling_prices` |
| Прочее | `env_data` |

JSON в `/etc/lan-discovery/`:

| Файл | Примеры |
|---|---|
| `*.json` | `users.json`, `settings.json`, `iptv-playlists.json`, `network.json`, `alarms.json`, `weather.json` |
| `notes/`, `secrets/` | заметки и «секреты» пользователей |
| `secret.key` | Flask `SECRET_KEY` (сессии/CSRF) |

Фоновые записи в БД делают **systemd-таймеры**, а не само приложение: на текущем хосте работает `backup-db.timer` (ежедневно 03:30); курсы валют и цены переработки обновляет фоновый поток `schedule` внутри приложения, чистку событий — `retention_loop`. Список и настройка — [Установка](Установка.md).

## Эксплуатация: скрипты жизненного цикла

| Скрипт | Что делает | Док |
|---|---|---|
| `install.sh` | Чистая установка: preflight → код → venv → конфиг → БД → юнит → health; идемпотентен, `--dry-run` | [Установка](Установка.md) |
| `update.sh` | Бэкап (код+settings+БД) → apply → verify → pip → restart → health, авто-rollback при сбое; `--rollback [TS]` | [Обновление](Обновление.md) |

## Тесты и CI

- `tests/unit` (46 тестов, без сети) + `tests/live` (маркер `live`,
  требует живую панель); конфиг — `pytest.ini`, зависимости —
  `requirements-dev.txt`.
- CI (`.github/workflows/ci.yml`): на каждый push/PR — pytest unit +
  `py_compile` всех модулей (ubuntu, Python 3.11).

## Безопасность и доступ

Модель доступа (роли, CSRF, открытые роуты, риски) — отдельная
страница: [Безопасность](Безопасность.md). Кратко: сессии Flask +
CSRF глобально; `@login_required`/`@admin_required`; роли
`admin` / `editor` / `guest`; из 172 роутов открыты только
`/login`, `/logout`, `/api/health`.

## Особенности реализации

- Рабочий процесс — dev-сервер Flask (`Running on all addresses (0.0.0.0)`), для продакшена можно поставить gunicorn за reverse-proxy (см. [Безопасность](Безопасность.md)).
- Долгие операции (клонирование SD, сканирование сети) выполняются в фоновых потоках, состояние отдаётся через `/api/.../status`.
- Само приложение слушает `0.0.0.0:8080`, поэтому доступно и по LAN-IP, и по IP WiFi-точки доступа.
