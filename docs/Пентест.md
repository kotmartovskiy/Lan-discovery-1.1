# Пентест — чек-лист проверки панели

Регламент самостоятельной security-проверки после значимых изменений и
периодически (раз в квартал). Основа threat model —
[Безопасность](Безопасность.md): закрытая LAN, «root by design»,
dev-Werkzeug осознанно. Чек-лист фиксирует, что уже проверено и не
регрессирует.

**Обозначения:** `[ ]` не проверено, `[x]` проверено, `[!]` обнаружено
(с записью в ROADMAP §8 или задачу). Тестировать на **обоих** узлах;
учётные данные — только тестовые, из окружения оператора (в документацию
не вписывать).

---

## 1. Периметр

- [ ] Панель доступна только из LAN (внешние интерфейсы/порт-forward
      отсутствуют: `ss -tlnp | grep -E '8080|8081'` — слушает ожидаемый интерфейс);
- [ ] restore-сервер (8081) поднимается только аварийно, после проверки —
      выключен: `systemctl is-enabled restore-server`;
- [ ] сторонние сервисы (Transmission :9091 и пр.) не проброшены наружу;
- [ ] firewall/роутер не пробрасывает 8080/8081 в WAN.

## 2. Аутентификация

- [ ] аноним на `/` и `/help` → 302 на `/login`;
- [ ] rate-limit логина: 6-я попытка с неверным паролем с одного IP → отказ
      (~5 минут), верная пароля в этот период тоже отклоняется;
- [ ] отключённый пользователь (`enabled=false` в users-файле) теряет
      действующую сессию (переход после TTL/при следующем запросе);
- [ ] TTL сессии: после 12 ч простоя запрос требует повторного входа;
- [ ] короткий пароль (< 8) отклоняется при смене;
- [ ] в `users.json` — bcrypt-хеши (`$2…`), ни одного SHA-256-фолбэка;
- [ ] cookie сессии: `HttpOnly`, `SameSite=Lax` (проверка в devtools/network).

## 3. Авторизация (роли)

- [ ] guest: `/api/settings` GET/POST и `/api/filemanager/*` → отказ (403/редирект);
- [ ] editor: правки контента есть, административные роуты закрыты;
- [ ] admin: filemanager работает, путь-валидация не даёт выйти за корень
      (`GET /api/filemanager/list?path=../../etc` → отказ);
- [ ] `/apps/terminal`: аноним и guest не открывают сессию; под admin —
      открывается, после выхода сессий `bash --login` не остаётся;
- [ ] SocketIO: `connect` отклоняется без admin-сессии (события
      `terminal_*` тем более).

## 4. CSRF / XSS / заголовки

- [ ] на страницах есть csrf-meta, форма входа содержит `csrf_token`;
- [ ] mutating-POST без токена → 400 (проверяется unit-тестом `test_security`);
- [ ] ответы содержат `X-Content-Type-Options: nosniff`,
      `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: same-origin`;
- [ ] пользовательский ввод (имена устройств, заметки, плейлисты) рендерится
      без выполнения HTML/JS (проверить `<img src=x onerror=alert(1)>` в имени
      устройства — после сохранения не должно срабатывать);
- [ ] CSP не введён — зафиксировано как осознанный residual (CDN-терминал).

## 5. Инъекции и ввод

- [ ] SQL: ручные запросы с кавычками в фильтрах/поиске не ломают запрос
      (все запросы параметризованы — см. Архитектура);
- [ ] shell: nettools-хосты принимаются только из белого формата
      (`_valid_host`): `;`, `&&`, обратные кавычки → отказ;
- [ ] path traversal: filemanager, скачивание бэкапов, загрузка файлов —
      `../` и абсолютные пути блокируются;
- [ ] SSRF: добавление URL (IPTV-плейлист, онлайн-радио, камеры) с
      `file://`, `localhost`, внутренними адресами — принимается/блокируется
      по задумке, зафиксировать поведение;
- [ ] заголовки ответов не содержат внутренних путей/версий сверх нужного.

## 6. Секреты и хранение

- [ ] `secret.key`, users-файл, settings — права доступа 600/644 по замыслу,
      не читаются гостевой ролью через панель;
- [ ] сейф паролей: запись/чтение только admin/editor (guest закрыт),
      в БД — Fernet-шифрование, старых base64-записей нет;
- [ ] `git grep` по репозиторию: нет рабочих паролей/ключей (санитайзер
      `tools/sanitize_docs.py` отрабатывает с 0 утечек);
- [ ] бэкапы в `/srv/backup-db` не экспортируются через web-роуты без авторизации.

## 7. Сеть и DoS

- [ ] `/api/network/check*` требуют входа;
- [ ] длительные операции (скан, inventory, bluetooth) не запускаются
      параллельно повторным POST (guard-флаги, см. P1-8);
- [ ] `subprocess`-вызовы (nmap, ping) идут с таймаутами, зависший вызов
      не вешает роут (проверить на недостижимом хосте);
- [ ] `/api/health` остаётся медленно-обновляемым кэшем (нет удара по БД
      на каждый чужой запрос).

## 8. Платформа / хост

- [ ] сервис под systemd с хардening-директивами юнита (см. Установка);
- [ ] после `systemctl restart` панель сама поднимается, данные целы;
- [ ] фоновые таймеры (бэкапы, погода) отработали по расписанию;
- [ ] логи (`journalctl -u lan-discovery -n 200`) без traceback и сырых
      секретов.

## 9. Фиксация результата

1. Заполнить чек-лист, отметить дату и узел (X96 / Orange Pi / иное).
2. Обнаруженное — в ROADMAP: регрессия → задача в §6, остаточный риск → §8.
3. Изменения кода → обычный цикл: бэкапы, тесты, коммит, деплой, CI.
4. Известные и принятые residual'ы (Werkzeug dev, root, CDN-терминал,
   HTTP без TLS в LAN) — не считаются находкой, но перепроверяются, что
   не выросли в объёме.
