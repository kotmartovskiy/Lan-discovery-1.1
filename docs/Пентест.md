# Пентест — чек-лист проверки панели

Регламент самостоятельной security-проверки после значимых изменений и
периодически (раз в квартал). Основа threat model —
[Безопасность](Безопасность.md): закрытая LAN, «root by design»,
dev-Werkzeug осознанно. Чек-лист фиксирует, что уже проверено и не
регрессирует.

**Обозначения:** `[ ]` не проверено, `[x]` проверено, `[!]` обнаружено
(с записью в ROADMAP §8 или задачу). Тестировать на **обоих** узлах;
учётные данные — только тестовые, из окружения оператора (в документацию
не вписывать).

**Прогон: 01.10.2026 — оба узла** (X96 `192.168.3.243` — версия 1.1,
Orange Pi `192.168.3.235` — версия 1.0; результаты совпали, кроме
отмеченного). Найденное на прогоне: guest `GET /api/settings` = 200 и
`restore-server` enabled — **вылечено в рамках №62** (фиксы ниже);
остальное отражено в residual'ах ROADMAP §8.

---

## 1. Периметр

- [!] Панель доступна только из LAN: `ss` — `0.0.0.0:8080` на обоих
      узлах; X96 — firewall отсутствует (`NO_UFW`), OP — ufw active,
      default deny incoming (8080 ALLOW Anywhere — для LAN). Отсутствие
      WAN-проброса 8080/8081/9091 **не подтверждается из этого окружения**
      (WAN-доступа нет) — residual §8; LAN-доступность подтверждена;
- [x] restore-сервер (8081): на прогоне был `enabled` и слушал на
      обоих — **обнаружено и отключено 01.10** (`systemctl disable
      now restore-server`; аварийный подъём — `systemctl start` вручную
      работает и у disabled);
- [x] сторонние сервисы (Transmission :9091): слушает `0.0.0.0`
      (вкладка Torrent рассчитана на LAN-доступ с хоста оператора);
      на OP ufw не разрешает 9091 (default deny), на X96 firewall нет
      — WAN-доступность см. п.1 residual;
- [ ] firewall/роутер не пробрасывает 8080/8081 в WAN — **не
      проверялось** (нет WAN-доступа/доступа к роутеру).

## 2. Аутентификация

- [x] аноним на `/`, `/help`, `/apps/*` → 302 на `/login`; API-роуты
      (`/api/settings`, `/api/network/check`, `/api/backup-status`,
      `/api/secrets`, `/api/events`) → 302; `filemanager/list` → 403;
- [x] rate-limit логина: подряд 7 неверных попыток; верная пароля в
      окне блокировки отклоняется (страница входа без 302); блок
      in-memory — снимается рестартом сервиса (проверено);
- [x] отключённый пользователь (`enabled=false`) теряет действующую
      сессию: следующий запрос → 302 (живой тест с временным юзером);
- [x] TTL сессии: по коду — `SESSION_TTL = 12 * 3600` в
      `modules/auth.py` (P0-5, `login_ts` обязателен); 12-часовой
      простой вживую не воспроизводился;
- [x] короткий пароль (< 8) отклоняется: `POST
      /api/users/<name>/password` → 400 «password too short», len=8 →
      200 (живой тест);
- [!] в `users.json` — `admin` bcrypt, **`user` и `guest` — legacy
      SHA-256** (до первого входа, затем lazy re-hash P0-5); пароли
      этих юзеров оператора неизвестны инструменту — сознательно не
      перехешированы — residual §8;
- [x] cookie сессии: `HttpOnly`, `SameSite=Lax` (live
      `test_login_sets_safe_session_cookie`).

## 3. Авторизация (роли)

- [x] guest: `GET/POST /api/settings` → **403** (после фикса №62:
      было `GET=200` — обнаружено этим прогоном, закрыто `admin_required`
      + unit `test_guest_cannot_read_settings`); `filemanager/*`,
      `/api/secrets`, `/api/users`, `POST /device/<ip>/name` → 403;
- [x] editor (role=user): правки контента есть (`POST
      /device/<ip>/name` → 302, имя сохранено и проверено в БД),
      административные роуты закрыты (`/api/settings` POST,
      `filemanager`, `/api/users` → 403);
- [x] admin: filemanager работает, путь-валидация не даёт выйти за
      корень: `path=../../etc` и `path=../etc` → 400 «Invalid path»
      (`_fm_path`: только абсолютные нормализованные пути); сам `/etc`
      admin-доступен — по модели «root by design»;
- [x] `/apps/terminal`: аноним → 302 (страница); сессия терминала —
      только admin (см. SocketIO); висящих `bash --login` после
      отключений не остаётся (pgrep — чисто);
- [x] SocketIO: живой тест python-socketio: анонимный `connect` →
      отказ (`ConnectionError`), admin-cookie → `connect: OK`; события
      `terminal_*` проверяют `_socket_is_admin()` (код).

## 4. CSRF / XSS / заголовки

- [x] на страницах есть csrf-meta (`base.html`, `base_app.html`),
      форма входа содержит `csrf_token` (живой grep);
- [x] mutating-POST без токена → 400 (`test_mutating_post_without_csrf_is_rejected`);
- [x] ответы содержат `X-Content-Type-Options: nosniff`,
      `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: same-origin`
      (unit + live, оба узла);
- [x] пользовательский ввод рендерится без выполнения HTML/JS: имя
      устройства `<img src=x onerror=alert(1)>` сохранено, в HTML —
      `&lt;img...` (0 незаэкранированных), имя восстановлено;
- [x] **CSP введён (№60)**: `Content-Security-Policy` на всех ответах,
      `script-src 'self' 'unsafe-inline'` без внешних CDN, vendor
      xterm/socket.io локально (`static/vendor/`) — терминал работает
      без интернета (unit + live на обоих узлах).

## 5. Инъекции и ввод

- [x] SQL: все запросы параметризованы (`?`-плейсхолдеры, см.
      [Архитектура](Архитектура.md)); свободных серверных
      строк-фильтров пользовательского ввода нет (поиск/фильтры UI —
      client-side и параметризованные `GET /api/events`), кавычки в
      query-путях не приводят к 500;
- [x] shell: nettools-хосты — только белый формат `_valid_host`: 6
      payload (`;reboot`, `$(...)`, backticks, `&&`, `|`, `%3B`) →
      «Недопустимый хост»; валидный `127.0.0.1` → ok (живой тест,
      JSON + X-CSRFToken);
- [x] path traversal: filemanager — 400 (п.3); роутов загрузки файлов
      нет; роуты restore (`/system/db-restore`, `emmc-restore`) под
      `@admin_required`; экспорт бэкапов без авторизации не найден
      (`/api/backup-status` аноним → 302);
- [x] SSRF: добавление IPTV-плейлиста (`POST /system/iptv/add`)
      сохраняло URL **без валидации схемы** — `file://`, localhost и
      внутренние адреса принимались (дальше плейлист скачивается
      сервером). **Закрыто 01.10.2026 (№66): принимаются только
      `http`/`https` с netloc; file://, gopher://, ftp://,
      javascript:, «//host», «http без netloc» → редирект без
      сохранения (юнит + живой прогон на X96: 302, счётчик
      плейлистов не вырос). localhost/внутренние адреса по http
      допустимы — LAN-модель, §8;**
- [x] заголовки ответов содержали версии ПО: `Server: Werkzeug/3.1.9
      Python/3.11.2` (X96) / `Werkzeug/3.1.3 Python/3.13.5` (OP) —
      residual §8 (связано с dev-Werkzeug). **Закрыто 01.10.2026
      (№66) на X96: `version_string` dev-сервера подменён →
      `Server: lan-discovery` (единственный заголовок, без версий);
      OP на версии 1.0 — остаётся до апдейта.**

## 6. Секреты и хранение

- [x] `secret.key`, `users.json`, `settings.json` — права `-rw-------`
      (600, root) на обоих узлах; через панель гость их не читает
      (`/api/settings` → 403 после фикса, `/api/secrets` → 403);
- [x] сейф паролей: запись/чтение `can_edit` (guest закрыт — живой
      403), в БД Fernet-шифрование (P0-4), старых base64-записей нет;
- [x] `git grep` по репозиторию: рабочих паролей/ключей нет,
      `python tools/sanitize_docs.py` → exit 0 (0 утечек);
- [x] бэкапы в `/srv/backup-db` не экспортируются через web-роуты без
      авторизации (роутов export нет, restore — admin-only).

## 7. Сеть и DoS

- [x] `/api/network/check*` требуют входа: аноним → 302, admin → 200;
- [x] длительные операции не запускаются параллельно повторным POST
      (guard-флаги P1-8: `start_scan_thread` idempotent — unit;
      inventory/bluetooth guards);
- [x] `subprocess`-вызовы идут с таймаутами: nmap `--host-timeout 3s`
      + `subprocess timeout=45` (`core/discovery.py`), `_cmd` timeout
      30, `gethostbyaddr` 1.5 с — зависший вызов не вешает роут;
- [x] `/api/health` — кэш 30 с (`_health_cache` в
      `modules/system_routes.py`): два подряд запроса ~50–60 мс,
      БД-удара на каждый чужой запрос нет.

## 8. Платформа / хост

- [x] сервис под systemd с hardening-директивами юнита (PHASE 8):
      `PrivateTmp`, `ProtectKernel{Tunables,Modules,ControlGroups}`,
      `LockPersonality`, `RestrictRealtime`; `ProtectHome`/
      `CapabilityBoundingSet` сознательно не включены — задокументировано
      в комментарии юнита («root by design»);
- [x] после `systemctl restart` панель сама поднимается, данные целы
      (многократно в течение дня на обоих узлах: restart → active →
      login 302, health ok);
- [x] фоновые таймеры отработали по расписанию: `weather-update.timer`
      (X96 17:38, OP 17:41), `backup-db.timer` (03:30/17:00) —
      `systemctl list-timers`;
- [x] логи `journalctl -u lan-discovery -n 200`: 0 `Traceback`,
      0 утечек `password=`/`secret.key` (оба узла).

## 9. Фиксация результата

1. Заполнить чек-лист, отметить дату и узел (X96 / Orange Pi / иное).
   **← прогон 01.10.2026, оба узла — заполнено.**
2. Обнаруженное — в ROADMAP: регрессия → задача в §6, остаточный риск → §8.
   **← guest settings и restore-server вылечены в №62; residual'ы
   (SHA-256 юзеров, WAN/файрвол) — §8; Server-версии и SSRF IPTV
   закрыты в №66.**
3. Изменения кода → обычный цикл: бэкапы, тесты, коммит, деплой, CI.
4. Известные и принятые residual'ы (Werkzeug dev, root, HTTP без TLS
   в LAN) — не считаются находкой, но перепроверяются, что не выросли
   в объёме.
